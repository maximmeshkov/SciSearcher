# SciSearcher: описание проекта

## Зачем это

SciSearcher — личная библиотека научных статей, которая наполняется сама. Он стоит на NAS или сервере и делает три вещи:

1. по расписанию ищет новые статьи по ключевым фразам и раскладывает их по тематическим библиотекам; в любую библиотеку можно добавить свои файлы и книги, а библиотека без фраз наполняется только вручную;
2. скачивает открытые PDF, принимает свои PDF и DjVu и разбирает их в текст, пригодный для нейросетей: формулы в LaTeX, таблицы, разделы, номера страниц, картинки графиков;
3. отдаёт этот текст агентам (Hermes, Codex и другим), чтобы они находили статьи и ссылались на них с DOI и страницей.

Разбор медленный, и это нормально: сервис работает в фоне, пока вы заняты своим. Одна установка — одна независимая библиотека. Дома на NAS и на сервере в университете ставится одно и то же, различаются только настройки.

## Как проходит одна статья

| Шаг | Что происходит | Состояние |
|---|---|---|
| 1. Найти | По расписанию SciSearcher спрашивает OpenAlex, Crossref, ленты RSS/Atom и IEEE Xplore по ключевым фразам библиотеки. Найденное проходит локальный фильтр: фразы, исключения, правило «любая» или «все». Дубликаты по DOI, ссылке и ID источника объединяются, одна статья может входить в несколько библиотек. | есть |
| 2. Скачать или добавить | Открытая копия PDF с лицензией CC BY или CC0. Если прямая ссылка не сработала и задан ключ OpenAlex — копия из кэша OpenAlex. Свои файлы (PDF, DjVu, JATS/TEI XML, Markdown, TXT) добавляются в библиотеку кнопками «Добавить файлы» и «Добавить папку» или прикрепляются к найденной статье. Файлы лежат на диске в `files/`, по хешу содержимого. | есть |
| 3. Разобрать | PDF и DjVu ставятся в очередь. DjVu сначала перерисовывается в PDF утилитой `ddjvu`. Отдельный поток отправляет файл в сервис MinerU и получает блоки страницы и картинки. Неудачная попытка повторяется с растущей паузой, недоступный MinerU не считается ошибкой статьи. | есть |
| 4. Подготовить | Из блоков собирается Markdown: метки страниц `<!-- page: N -->`, заголовки разделов, формулы `$…$` и `$$…$$`, таблицы в HTML, подписи и ссылки на картинки графиков, рисунков и таблиц (`/api/files/<хеш>.jpg`). Колонтитулы и номера страниц отбрасываются, список литературы хранится отдельно. | есть |
| 5. Индексировать | Модель эмбеддингов кодирует фрагменты полных текстов. В Qdrant сохраняются векторы, текст, страница и библиотека. Очередь переживает выключение компьютера с моделью. | есть |
| 6. Задать вопрос | Веб-интерфейс ищет фрагменты и передаёт их чат-модели. Агент может использовать `/mcp` и инструменты `list_libraries`, `search_library`, `read_article`. | есть |

Без MinerU (пустой `MINERU_URL`) шаги 3–4 заменяет прежний путь: сырой текст из `pypdf` с метками `## Страница N`.

## Из чего состоит

```
compose.yaml          SciSearcher, планировщик, каталог и очереди (том library-data)
compose.mineru.yaml   опциональный локальный MinerU с томом mineru-models
QDRANT_URL            существующий внешний Qdrant, доступный по HTTP(S)
```

| Файл | Чем владеет |
|---|---|
| `app.py` | HTTP-интерфейс и API, проверка доступа, приём файлов по частям, `Indexer`: поиск по расписанию, скачивание PDF, очередь разбора |
| `catalog.py` | База SQLite: библиотеки, статьи, вложения (хеши файлов), слияние дубликатов, очередь разбора, журнал запусков; одноразовый перенос старых файлов из базы в `files/` |
| `files.py` | `FileStore`: папка `files/`, файлы по SHA-256 содержимого, одинаковое содержимое хранится один раз |
| `article_folders.py` | Папка для чтения и переноса статьи, метаданные и относительные ссылки на рисунки |
| `discovery.py` | Повторный поиск копий в источниках, приоритет ручных запросов и учёт причин неудачи |
| `rag.py` | Профили и окна работы моделей, индексирование в Qdrant, поиск по библиотеке и ответы с цитатами |
| `mcp_rag.py` | MCP поверх тех же функций поиска и чтения |
| `documents.py` | Текст из файлов: PDF через `pypdf`, JATS/TEI, Markdown, TXT; проверка сигнатуры PDF и DjVu; DjVu → PDF через `ddjvu`; сборка Markdown из разбора MinerU; нарезка на фрагменты для экспорта |
| `mineru.py` | Клиент API MinerU: создать задачу, отправить файл с диска потоком, дождаться, забрать разбор и картинки |
| `sources/` | Адаптеры источников: `openalex.py`, `crossref.py`, `rss.py`, `ieee.py`; `net.py` — загрузчик только с публичных адресов |
| `static/` | Веб-интерфейс без сборки: `index.html`, `app.js`, `style.css` |
| `tests/` | Проверки `unittest`, в том числе сквозной прогон через HTTP с тестовыми ответами источников |

Таблицы базы: `libraries`, `articles`, `article_keys` (ключи для поиска дубликатов), `article_sources`, `memberships` (статья ↔ библиотека), `attachments` (статья, формат, хеш файла в `files/`), `parse_queue`, `article_references`, `runs`, `catalog_metadata`. Свой файл получает запись с ключом `upload:<хеш>`: повторная загрузка того же содержимого находит ту же запись.

## Дома и в университете

Обе установки собираются из одного `compose.yaml` и не синхронизируются. Агент подключает их как два MCP-сервера, например `scisearcher-home` и `scisearcher-uni`, и ищет в обеих.

| | Домашний NAS (Intel N100, больше 16 ГБ памяти) | Сервер в университете |
|---|---|---|
| Разбор | MinerU на процессоре, `PARSE_WORKERS=1` | Больше ядер — больше `PARSE_WORKERS` |
| Доступ | Пароль, если интерфейс открыт не только на самом NAS | Пароль и HTTPS обязательны, если пользуются коллеги |
| RAG | Профили рабочего ПК и резервного сервера с разрешёнными окнами нагрузки | Сервер моделей в сети университета, отдельные настройки и каталог |

Настройки установки в `.env`: `INDEXER_PASSWORD`, `SCISEARCHER_BIND`, `SCISEARCHER_PORT`, ключи источников (`OPENALEX_API_KEY`, `IEEE_API_KEY`, `CROSSREF_MAILTO`), `MINERU_URL`, `MINERU_TIER`, `MINERU_DEVICE`, `MINERU_TIMEOUT_HOURS`, `PARSE_WORKERS`, `MAX_DOWNLOAD_MB`. Подробности — в [README](README.md).

## Как управлять

- **Темы и источники** — веб-интерфейс: библиотека = набор статей и файлов плюс необязательный поиск (ключевые фразы, исключения, источники, расписание). Кнопка «Искать сейчас» запускает поиск вне расписания. Без фраз библиотека ничего не ищет и наполняется вручную; поиск добавляется в настройках в любой момент.
- **Свои файлы и книги** — «Добавить файлы» или «Добавить папку» в любой библиотеке; к найденной статье — в окне статьи. Размер не ограничен. Папка на NAS, которую SciSearcher забирает сам, — в планах.
- **Что происходит** — журнал запусков поиска, у библиотеки счётчик «Ждут разбора», у статьи состояние PDF и разбора с текстом ошибки.
- **Резервная копия** — снимок датасета или каталог, `files/` и `articles/`. Индекс Qdrant можно построить повторно. Команды есть в README.
- **Обновление из исходников** — после резервной копии выполни `git pull --ff-only` и `docker compose up -d --build`.

## Как расширять

| Что добавить | Где | Что ещё меняется |
|---|---|---|
| Новый источник статей | Модуль в `sources/` по образцу `openalex.py`: `SPEC` с полями формы и функция `search` или `pages`; имя модуля в `sources/__init__.py` | Ничего: форма и планировщик берут настройки из реестра |
| Другой разборщик (OCR для сканов, другой конвертер) | Своя функция «PDF → блоки» рядом с `mineru.py` и сборка Markdown в `documents.py` | Очередь и интерфейс остаются |
| Новый агент | Адрес SciSearcher с путём `/mcp` в конфигурации клиента | Клиенту нужен транспорт Streamable HTTP |
| Другая модель | Профиль в настройках моделей | При смене модели эмбеддингов строится отдельная коллекция Qdrant |

## Почему MinerU

Сравнение на 14 открытых статьях по load-pull (141 страница, процессор Intel i5-10400, без видеокарты):

| | pypdf | Docling 2.153 | MinerU 4.2.3 (standard) |
|---|---|---|---|
| Сбоев | 1 из 14 | 0 | 0 |
| Секунд на страницу | 0,22 | 1,9 | 21 (модели загружались заново для каждой статьи) |
| Заголовков разделов | 0 | 195 | 181 |
| Таблиц | 0 | 20 | 31 |
| Выносных формул в LaTeX | 0 | 0 (123 заменены меткой) | 119 |
| Формул в строке в LaTeX | 0 | 0 | 1565 |
| Слов, разорванных переносом | 795 | 0 | 0 |

Docling без модели формул теряет все выносные формулы, а с ней на процессоре не закончил статью на 5 страниц за 65 минут процессорного времени. Для научных статей это неприемлемо. Во время разбора MinerU занимал около 3,2 ГБ памяти.

Лицензия MinerU — Apache 2.0 с дополнениями. Отдельная коммерческая лицензия нужна при более чем 100 млн пользователей в месяц или выручке больше 20 млн долларов в месяц. Упоминание MinerU обязательно при онлайн-сервисе для третьих лиц. Лицензии моделей MinerU не проверялись.

## Состояние и планы

| Этап | Что даёт | Состояние |
|---|---|---|
| Сбор | Поиск по источникам, библиотеки, скачивание PDF, экспорт Markdown и JSONL | есть |
| А — разбор | PDF через MinerU в фоновой очереди, картинки графиков | есть, проверено в Docker Desktop. Производительность конкретного N100 нужно измерять на нём |
| Свои файлы | Библиотеки без поиска, загрузка файлов и папок, DjVu, файлы на диске без предела размера | есть; DjVu проверен только тестом с подменой `ddjvu` |
| Б — поиск и MCP | Поиск в Qdrant, чтение страниц и ответ в веб-интерфейсе | есть |
| В — «Входящие» | Папка на NAS, которую SciSearcher забирает сам; DOI из текста, метаданные из Crossref | не сделано |
| Г — паспорта | Ключевые цифры статьи через LLM (LM Studio) | не сделано |

Известные ограничения:

- PDF с `pmc.ncbi.nlm.nih.gov` не скачиваются: сервер отдаёт HTML вместо файла.
- Для карточки без файла выполняется отдельный поиск по идентификаторам. Получение открытого PDF зависит от доступных копий, ответов издателя и лицензии конкретной версии.
- Скачивание из интернета ограничено `MAX_DOWNLOAD_MB` (200 МБ); свои файлы — нет.
- Значения с графиков не извлекаются: MinerU отдаёт график картинкой.
- Обложки издателей (например, IOP) попадают в текст первой страницы.
- Без пароля доступ проверяется только по заголовку `Host`; при запуске в сети без пароля в журнале появляется предупреждение.
