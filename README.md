# SciSearcher

Локальный индексер научных публикаций для нескольких тематических библиотек. В браузере задаются ключевые фразы, исключения, история, расписание и источники для каждой библиотеки. Одна статья может входить в несколько библиотек. DOI и исходная ссылка сохраняются при экспорте.

## Запуск

На машине с Docker и Compose из каталога проекта:

```sh
docker compose up -d --build
```

Интерфейс открывается на `http://127.0.0.1:8738`. Каталог, полученные файлы и журнал находятся в томе `library-data`. Для доступа по сети задай `SCISEARCHER_BIND` с адресом хоста, `INDEXER_PASSWORD` и открой тот же порт на хосте. Имя пользователя `admin`. Для доступа через недоверенную сеть размести интерфейс за HTTPS. На TrueNAS SCALE можно запускать Compose из каталога в постоянном датасете с Docker или использовать Custom App с предварительно собранным образом и томом `/data`. При bind-монте контейнер пишет от UID/GID `10001`. [Документация TrueNAS](https://www.truenas.com/docs/scale/26/apps/installcustomappscreens/)

Местный запуск с Python 3.14 и `pypdf` из `requirements.txt`:

```sh
python app.py --port 8738
```

Данные такого запуска хранятся в `data/`, путь можно передать через `--data`. Фоновый сбор запускается в процессе сервиса. Кнопка «Искать сейчас» ставит выбранную библиотеку в очередь немедленно.

## Поиск и экспорт

- Создай библиотеку и задай `load-pull` как ключевую фразу. Варианты `load-pull`, `load pull` и `load‑pull` равнозначны при локальном сопоставлении. Для второй библиотеки можно добавить `GaN` и выбрать совпадение со всеми фразами.
- Добавь OpenAlex, Crossref или конкретные ленты RSS/Atom журналов. Для OpenAlex можно задать `OPENALEX_API_KEY`, для Crossref — `CROSSREF_MAILTO`. IEEE Xplore использует только Metadata API с `IEEE_API_KEY`. Подписочный PDF можно добавить к записи через интерфейс, если условия источника разрешают нужное использование. Штатный веб-прокси IEEE не используется для автоматической выкачки.
- Для каждой фразы поисковый модуль отдаёт до 100 результатов в одном проходе. В ленте объём и глубину истории задаёт её издатель. Архив сохраняет уже добавленные статьи при изменении запроса. Ошибки источников и достижения лимита видны в журнале.
- У каждой статьи отмечен уровень текста. Прямая открытая PDF-копия загружается, когда источник предоставляет подходящую ссылку и в библиотеке включено скачивание. Можно приложить свой PDF, JATS/TEI XML, Markdown или TXT к найденной записи. PDF со сканами понадобится предварительно распознать. Страница для PDF или путь раздела для структурированного текста сохраняются в фрагментах, если их можно извлечь.
- **Markdown** представляет подборку одним текстовым файлом. **JSONL** содержит текстовые фрагменты, DOI, ссылку, тип содержимого и `library_ids` для фильтрации. Векторизатор читает `text`, сохраняет остальные поля как метаданные и использует `id` как UUID точки. Переключатель полного текста отбрасывает аннотации и записи без текста. Эмбеддинги рассчитывает выбранный внешний индексатор.

## Как добавить источник

Парсеры находятся в `sources/`. Каждый модуль объявляет `SPEC` для формы настройки и реализует одну функцию. Добавь имя модуля в список в `sources/__init__.py`. Интерфейс и планировщик получают настройки из того же реестра.

```python
SPEC = {
    "kind": "new_site",
    "label": "Журнал или каталог",
    "description": "Поиск через официальный API источника.",
    "mode": "search",
    "fields": [],
}

def search(source, keyword, since, limit, get):
    # Вызови API через get(url, max_bytes, accept="application/json").
    # Верни записи в общем формате. Пустой результат — [].
    raise NotImplementedError
```

Режим `search` получает одну фразу за вызов. Режим `feed` вызывается один раз с пустой фразой, после чего ядро применяет фильтры библиотеки. `since` передаётся как `datetime.date`. Для пользовательского поля укажи в `fields` значения `key`, `label`, `type` (`text` или `url`), `required`, `max_length` и при необходимости `placeholder` или `pattern`.

Адаптер возвращает список словарей. Поле `title` обязательно. Дополнительные поля задаются по мере наличия данных: `doi`, `abstract`, `url`, `pdf_url`, `published` в формате `YYYY-MM-DD`, `authors` и `keywords` как списки строк, `venue`, `license`, `external_id`. `pdf_url` используется загрузчиком только для подходящей открытой копии. Ключи API берутся в самом модуле из окружения. Единый `get` ограничивает объём ответа и обрабатывает только публичные HTTP(S) адреса.

## Проверка

```sh
python -m unittest discover -s tests -v
```

Тест проходит через HTTP и планировщик, с тестовыми ответами трёх источников. Проверяются разнесение `load-pull` по библиотекам, дедупликация DOI, скачивание PDF, добавление XML и оба формата экспорта.
