# SciSearcher

Локальный индексер научных публикаций для нескольких тематических библиотек. В браузере задаются ключевые фразы, исключения, история, расписание и источники для каждой библиотеки. В любую библиотеку можно добавлять свои файлы: PDF, DjVu, Markdown, TXT, JATS/TEI XML. Библиотека без фраз и источников наполняется только вручную. Одна статья может входить в несколько библиотек. DOI и исходная ссылка сохраняются при экспорте.

Зачем проект, как устроен, как им управлять и что в планах — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

На машине с Docker и Compose первый запуск из GitHub выглядит так.

```sh
git clone https://github.com/maximmeshkov/SciSearcher.git
cd SciSearcher
docker compose up -d --build --wait
```

Интерфейс открывается на `http://127.0.0.1:8738`. По умолчанию Compose создаёт **один контейнер SciSearcher**. Он собирает статьи и извлекает текстовые слои PDF через pypdf. Для сканов, формул, рисунков и DjVu подключи MinerU. Для вопросов по статьям укажи адрес уже работающего Qdrant и сервер моделей.

## От темы диссертации до ответа со страницей

1. Создай библиотеку **Load-pull**, добавь фразу `load-pull` и выбери источники. Для обзора за весь период включи поиск по всему архиву и скачивание открытых PDF. Нажми **Искать сейчас**. Для другой темы создай вторую библиотеку со своими фразами и журналами.
2. Нажми **Без полного текста**, чтобы увидеть, чего не хватает. SciSearcher повторно ищет открытые копии уже известных статей по DOI или ID. Кнопка **Найти полный текст** в карточке ставит конкретную статью первой в очередь. Если PDF получен через университетский доступ, открой ту же карточку и прикрепи файл. Так он сохранит связь с DOI. Загружай папку при добавлении отдельных работ, для которых ещё нет карточек.
3. Открой **Вопросы по статьям → Настроить модели**. Укажи адрес существующего Qdrant, доступный с NAS, например `http://192.168.1.20:6333`. При установке в общей сети Docker подойдёт DNS-имя контейнера, например `http://qdrant:6333`. Затем укажи адрес OpenAI-совместимого сервера, например `http://192.168.1.50:1234/v1` для LM Studio на рабочем ПК. Сохрани профиль, запроси список моделей и выбери модель эмбеддингов для поиска и чат-модель для ответов. Для Docker Desktop адрес компьютера с Docker — `http://host.docker.internal:1234/v1`.
4. Для ночной индексации укажи дни, часовой пояс и окно, например с 23:00 до 07:00. Начало определяет день недели у окна через полночь. Добавь второй профиль с другим адресом и приоритетом для резервного сервера. Меньшее число означает более высокий приоритет. Для продолжения того же индекса используй тот же идентификатор модели эмбеддингов. Окно ограничивает запросы к моделям данного профиля, в том числе при вопросах. Для дневных вопросов укажи доступный днём профиль.
5. Посмотри число **проиндексированных** текстов. Задай вопрос, например «На какой плате авторы реализовали RFSoC-систему load-pull и на какой частоте испытывали усилитель?». Открой источник у ответа, прочти фрагмент и перейди на страницу PDF. Для поиска без генерации нажми **Найти фрагменты**. При выключенном компьютере NAS продолжает сбор. В подходящее окно работник автоматически продолжает индексацию.
6. Неподходящую статью отправь **В чёрный список**. Выбери одну библиотеку или все. Статья исчезает из поиска и ответов и остаётся в списке для восстановления. Удаление файлов и текста требует отдельного подтверждения. Восстановление после физического удаления возвращает карточку, файлы придётся получить заново.

### Что лежит на NAS

| Где | Что хранится |
|---|---|
| `/data/articles/<год>/<папка статьи>/` | `original/source.pdf` или оригинал другого формата, `text/article.md`, рисунки в `figures/`, `metadata/article.json` с DOI. Библиография при наличии лежит в `text/references.md`. Относительные ссылки работают при просмотре папки с другого компьютера. |
| `/data/catalog.sqlite3` и `/data/files/` | Каталог, извлечённый текст, библиотеки, настройки, очереди, постоянные исключения и дедуплицированные исходные файлы. Статья в нескольких библиотеках использует общие файлы. |
| Внешний Qdrant | Векторы и фрагменты со страницей и принадлежностью к библиотекам. SciSearcher создаёт свою коллекцию, отправляет вопрос модели эмбеддингов, подбирает фрагменты и передаёт их чат-модели. При смене модели эмбеддингов строится другая коллекция. Тома и резервные копии Qdrant находятся у владельца этого сервера. |

На TrueNAS задай в `.env` значение `SCISEARCHER_DATA=/mnt/tank/scisearcher/library` и предоставь контейнерному UID 10001 запись в этот датасет. Папку `articles` удобно читать через SMB. Адрес существующего сервера векторов можно сразу задать в `QDRANT_URL`. Ключ для этого адреса задаётся в `QDRANT_API_KEY`. Пустой адрес позволяет сначала заняться сбором. Для подключения к существующей общей сети Docker используй в Compose `networks` с `external: true` и именем этой сети.

Если существующий контейнер Qdrant доступен только внутри сети Docker, положи рядом с `compose.yaml` файл `compose.override.yaml`. В этом примере `nas-services` — имя уже существующей сети, а `qdrant` — имя контейнера в ней.

```yaml
services:
  scisearcher:
    networks: [default, vector-service]
networks:
  vector-service:
    external: true
    name: nas-services
```

Примени конфигурацию командой `docker compose up -d` и укажи `http://qdrant:6333` в веб-форме. Если подключаешь и локальный MinerU, используй `docker compose -f compose.yaml -f compose.mineru.yaml -f compose.override.yaml up -d --build`. Если Qdrant уже доступен по адресу хоста, достаточно указать этот адрес в форме. Управление контейнером и томом Qdrant остаётся у его собственной установки.

По кнопке источника SciSearcher показывает оригинальную страницу PDF как изображение. Формулы и рисунки рендерит Poppler, включённый в Docker-образ. Также можно открыть сам PDF и сравнить его с распознанным текстом. При запуске напрямую из Python графический просмотр доступен, если `pdftoppm` находится в `PATH`.

Для обычного OpenAI-совместимого сервера оставь стандартный режим генерации. Для LM Studio на компьютере с ограниченной памятью профиль позволяет выключить рассуждения через нативный API и задать максимальное число токенов ответа. Это параметры чат-модели, модель эмбеддингов продолжает работать через тот же профиль.

### Как подключить своего ИИ-агента

В клиенте с поддержкой MCP выбери транспорт **Streamable HTTP** и URL `https://<адрес-SciSearcher>/mcp`. Используй тот же доступ, что и в веб-интерфейсе. При HTTP Basic настрой в клиенте заголовок `Authorization: Basic <base64(admin:пароль)>` и HTTPS. Сначала вызови `list_libraries`, затем `search_library` с `library_id` и `query`. Инструмент `read_article` принимает `library_id`, `article_id` и необязательные `page` и `offset`. Он отдаёт текст страницы и ссылку на локальную копию. Для домашней и университетской установок добавь в клиент два адреса. Данные и настройки каждой установки независимы.

Для доступа по сети задай `SCISEARCHER_BIND` с адресом хоста и `INDEXER_PASSWORD` для пользователя `admin`. Без пароля сервис принимает только запросы с локальным адресом в заголовке `Host`. Это защищает от подмены DNS через браузер, но не от клиента в сети: он может сам прислать `Host: localhost`. Поэтому без пароля оставляй `SCISEARCHER_BIND` на `127.0.0.1`. Внутри контейнера сервис слушает `0.0.0.0`, и без пароля журнал при запуске всегда показывает предупреждение. Для доступа через недоверенную сеть размести интерфейс за HTTPS.

При установке через **Apps → Install via YAML** в TrueNAS укажи готовый образ SciSearcher из своего реестра вместо локального `build` и подключи датасет к `/data`. При развёртывании из клона через Docker Compose образ собирается на месте. Открой порт контейнера `8080` через `SCISEARCHER_BIND` и установи `INDEXER_PASSWORD`. Если в университете уже работают MinerU, Qdrant и сервер моделей, укажи адреса этих трёх сервисов. Для локального MinerU есть дополнительный файл `compose.mineru.yaml`. [Документация TrueNAS](https://www.truenas.com/docs/scale/26/apps/installcustomappscreens/)

Местный запуск с Python 3.14 и `pypdf` из `requirements.txt`:

```sh
python app.py --port 8738
```

Данные такого запуска хранятся в `data/`, путь можно передать через `--data`. Фоновый сбор запускается в процессе сервиса. Кнопка «Искать сейчас» ставит выбранную библиотеку в очередь немедленно.

## Свои файлы и книги

Кнопки «Добавить файлы» и «Добавить папку» есть у каждой библиотеки. Папка выбирается в браузере целиком, с подпапками; неподходящие файлы пропускаются, итог показывается одной строкой. Каждый файл становится отдельной записью, название берётся из имени файла. Повторная загрузка того же содержимого, даже под другим именем, не создаёт дубль и не запускает разбор заново. Свой файл к найденной статье по-прежнему прикрепляется в окне статьи.

Размер своих файлов не ограничен: загрузка пишется на диск по частям. Ограничено только скачивание из интернета, `MAX_DOWNLOAD_MB`, по умолчанию 200 МБ, — чтобы чужой сервер не заполнил диск.

Библиотека без ключевых фраз ничего не ищет: источники в ней не сохраняются, планировщик её не запускает. Чтобы добавить поиск, впиши фразы и источники в настройках. Чтобы класть файлы в библиотеку с поиском, ничего менять не нужно.

DjVu MinerU 4.2.3 не принимает, поэтому SciSearcher сначала перерисовывает страницы в PDF утилитой `ddjvu` из [DjVuLibre](https://dyn.manpages.debian.org/trixie/djvulibre-bin/ddjvu.1.en.html) (в образе `scisearcher` она есть), а затем отдаёт их MinerU. Формулы и рисунки распознаются со страниц как с картинок. Без MinerU DjVu не принимается. Для местного запуска без Docker нужна установленная `ddjvu` в `PATH`.

## Разбор PDF через MinerU

При запуске без MinerU один фоновый обработчик проверяет ранее скачанные PDF без текста. Если в них есть текстовый слой, он становится доступен индексации. У сканов появляется отметка о необходимости OCR. При подключении MinerU очередь принимает и сканы, и PDF с предварительно извлечённым текстом.

SciSearcher записывает идентификатор отправленного задания до загрузки файла. После обрыва связи или перезапуска он запрашивает состояние задания у того же сервера и забирает готовый результат. При замене исходного файла учитывается его новый SHA-256.

Подключи уже работающий разборщик через `MINERU_URL`. Если своего разборщика нет, выполни `docker compose -f compose.yaml -f compose.mineru.yaml up -d --build --wait`. Получатся два контейнера, SciSearcher и MinerU. MinerU 4.2.3 извлекает формулы в LaTeX, таблицы, подписи к рисункам, разделы и номера страниц. Графики сохраняются как изображения. Неудачные попытки повторяются с растущей паузой, а недоступный сервер оставляет статью в очереди. [MinerU](https://github.com/opendatalab/MinerU)

При первом запуске `mineru` скачивает около 1,4 ГБ моделей в том `mineru-models`, поэтому `docker compose up --wait` в первый раз идёт дольше. На процессоре Intel i5-10400 разбор 14 статей занял в среднем 21 с на страницу, причём модели загружались заново для каждой статьи. Во время разбора процесс занимал около 3,2 ГБ памяти.

Настройки в `.env`:

- `MINERU_CPUS` — лимит CPU локального контейнера MinerU, например `2` для двух ядер. По умолчанию Docker разрешает все доступные ядра. Число одновременно разбираемых PDF задаётся отдельно.
- `PARSE_WORKERS` — сколько статей разбирается одновременно, по умолчанию 1. На сервере с большим числом ядер можно поднять.
- `MINERU_TIER` — уровень разбора для запросов: `flash`, `basic` или `standard`. Пустое значение оставляет выбор MinerU.
- `MINERU_API_KEY` — ключ для внешнего сервера MinerU, если на нём включена авторизация.
- `MINERU_DEVICE` — `cpu` по умолчанию.
- `MINERU_TIMEOUT_HOURS` — сколько ждать разбора одного файла, по умолчанию 48 часов. Книга на сотни страниц на процессоре N100 может идти часами.
- `MAX_DOWNLOAD_MB` — предел скачивания PDF из интернета, по умолчанию 200.
- `MINERU_URL` — адрес другого сервера MinerU, например на машине с видеокартой. Пустое значение `MINERU_URL=` отключает MinerU, и текст извлекается через `pypdf`, как раньше.

Местный запуск без Docker: `mineru-kit api-server --port 8000` в отдельном окружении с `pip install mineru==4.2.3`, затем `MINERU_URL=http://127.0.0.1:8000 python app.py`. PDF, скачанные до включения MinerU, ставятся в очередь разбора при следующем запуске.

## Резервная копия

На TrueNAS предпочтителен согласованный снимок датасета `/data`. Для переноса без ZFS сохрани каталог, файлы и папки статей. На время копирования исключи изменение и удаление файлов. SQLite Backup API снимает согласованную копию открытой базы. Храни результат вне тома сервиса.

```sh
docker compose exec -T scisearcher python -c 'import sqlite3; src = sqlite3.connect("file:/data/catalog.sqlite3?mode=ro", uri=True); dst = sqlite3.connect("/tmp/scisearcher-backup.sqlite3"); src.backup(dst); dst.execute("PRAGMA journal_mode=DELETE"); dst.close(); src.close()'
docker compose cp scisearcher:/tmp/scisearcher-backup.sqlite3 ./scisearcher-backup.sqlite3
docker compose cp scisearcher:/data/files ./scisearcher-files
docker compose cp scisearcher:/data/articles ./scisearcher-articles
```

Для проверки восстановления положи снимок как `catalog.sqlite3` и папки как `files` и `articles` в новый каталог данных. Восстанавливай с отдельным Qdrant, особенно при одновременной работе копии и оригинала. На пустом Qdrant индекс строится заново, когда доступна модель. Проверь библиотеку, один PDF и ответ со страницей. [SQLite Backup API](https://sqlite.org/backup.html)

Версии до хранения файлов на диске держали PDF внутри базы. При первом запуске новой версии они один раз переносятся в `files/`.

## Поиск и экспорт

OpenAlex — библиографический каталог. Для статьи он может вернуть DOI, авторов и несколько мест публикации, в том числе адрес PDF и лицензию конкретной копии. Crossref получает метаданные DOI от издателей. Поэтому количество найденных карточек, локальных PDF и текстов, уже доступных в поиске ИИ, видно в трёх разных счётчиках. [OpenAlex API](https://help.openalex.org/api/) · [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)

- Создай библиотеку и задай `load-pull` как ключевую фразу. Варианты `load-pull`, `load pull` и `load‑pull` равнозначны при локальном сопоставлении. Для второй библиотеки можно добавить `GaN` и выбрать совпадение со всеми фразами.
- Добавь OpenAlex, Crossref или конкретные ленты RSS/Atom журналов. Для OpenAlex можно задать `OPENALEX_API_KEY`, для Crossref — `CROSSREF_MAILTO`. IEEE Xplore использует только Metadata API с `IEEE_API_KEY`. Подписочный PDF можно добавить к записи через интерфейс, если условия источника разрешают нужное использование. Штатный веб-прокси IEEE не используется для автоматической выкачки.
- OpenAlex и Crossref перебирают страницы выдачи по каждой ключевой фразе. Для поиска по всему архиву включи «Искать за всё доступное время». На широкий запрос Crossref может отдать много кандидатов, просмотр которых занимает время. В библиотеку попадают записи, прошедшие локальный фильтр. В RSS/Atom объём и глубину истории задаёт издатель. OpenAlex без ключа ограничивает один запрос первыми 10 000 записями, ключ позволяет использовать курсор. Статьи с предыдущих запусков сохраняются. Ошибки источников и неполные проходы видны в журнале.
- У каждой статьи видны состояние PDF, очередь разбора и ошибки. Фильтры показывают готовые тексты или статьи, которым требуется файл. После обработки MinerU в источниках ответа появляются страницы PDF, для структурированного текста доступны разделы.
- Если прямой PDF недоступен и задан `OPENALEX_API_KEY`, SciSearcher проверяет кэш OpenAlex по исходному ID статьи. Он пробует кэшированную копию с лицензией CC BY или CC0. Такие запросы используют квоту API. [Кэш OpenAlex](https://help.openalex.org/access/fulltext/)
- **Markdown** экспортирует подборку одним файлом. **JSONL** содержит текстовые фрагменты, DOI, тип содержимого и `library_ids` для внешних инструментов. Встроенный поиск через Qdrant индексирует полные тексты автоматически.

## Как добавить источник

Для нового сайта добавь один модуль в `sources/` и его имя в реестр. Образец, интерфейсы поиска и получения PDF и сквозной тест описаны в [SOURCES.md](SOURCES.md).

## Проверка

```sh
python -m unittest discover -s tests -v
```

Тест проходит через HTTP и планировщик, с тестовыми ответами трёх источников. Проверяются разнесение `load-pull` по библиотекам, дедупликация DOI, скачивание PDF, добавление XML и оба формата экспорта.
