# Как добавить источник статей

1. Создайте модуль в `sources/` и добавьте его имя в `_BUILTIN_MODULES` в `sources/__init__.py`. При старте сервис импортирует перечисленные модули. Если импорт или проверка описания не удались, журнал покажет имя пропущенного модуля.
2. Опишите настройки через `SPEC`. Редактор библиотеки получает список полей из `GET /api/sources`, а сервер проверяет их при сохранении. Адрес для запросов, фильтр коллекции или ISSN могут отличаться у библиотек. Ключ провайдера читайте из переменной окружения сервера, поскольку пользователь видит значения полей библиотеки.
3. Реализуйте `search`. Для постраничной выдачи добавьте `pages`, для получения полного текста уже известной работы — `resolve`. Эти функции вызываются и при ручном запуске, и в фоновом задании.

### Пример адаптера

По умолчанию реестр разрешает экспорт аннотации источника. Если условия источника требуют оставить её только в карточке, укажите `"export_abstract": False` в `SPEC`. При объединении дублей каталог предпочитает аннотацию из источника, допускающего экспорт. При временном отсутствии модуля экспорт его аннотаций приостанавливается.

Условный журнал ниже выдаёт JSON с массивом `articles`. Названия полей и адреса запросов замените на значения для своего сайта.

```python
from .common import fetch_json, record

SPEC = {
    "kind": "rf_journal", "label": "RF Journal",
    "description": "Поиск статей в коллекции журнала.", "mode": "search",
    "fields": [{"key": "collection", "label": "Коллекция", "type": "text",
                "required": True, "max_length": 80}],
}


def search(source, keyword, since, limit, get):
    query = {"collection": source["collection"], "q": keyword, "limit": limit}
    if since.year > 1:
        query["from"] = since.isoformat()
    response = fetch_json(get, "https://journal.example/api/articles", query)
    return [record("rf_journal", title=item["title"], doi=item.get("doi"),
                   external_id=item["id"], published=item.get("date"), url=item.get("landing_page"))
            for item in response["articles"]]
```

* `kind` — постоянный идентификатор источника. Публичные типы и поддерживаемые поля описаны в `sources/types.py`. Поисковые модули получают одну ключевую фразу за вызов. Для RSS или Atom укажите `mode="feed"`: сервис читает ленту один раз и проверяет фразы в результатах.
* `search(source, keyword, since, limit, get)` возвращает список до `limit` записей. Название обязательно. DOI, постоянная ссылка и идентификатор издателя помогают объединить результаты из разных источников. Атрибут `pdf_url` означает прямую ссылку на разрешённую к загрузке копию. Положите адрес страницы статьи в `url`.
* `pages(source, keyword, since, limit, get)` по очереди выдаёт списки публикаций, пока у провайдера есть следующая страница. `limit` ограничивает размер страницы. Уже пройденные страницы сохраняются при сбое. Когда API поддерживает пагинацию, реализуйте этот метод, иначе полностью заполненная страница будет отражена в журнале как частичная выдача. Примеры работы с курсором есть в `sources/crossref.py` и `sources/openalex.py`.
* `resolve(doi, external_id, get)` выдаёт возможные копии как тройки `(download_url, license, public_url)`. Проверьте идентичность работы и условия получения файла. Временный адрес скачивания может содержать токен. В `public_url` отдайте постоянный адрес без токена — он попадёт в каталог и метаданные папки. При отсутствии копии завершите генератор без результатов. Каждый модуль получает собственные идентификаторы и при необходимости может искать только по DOI. Пример есть в `sources/openalex.py`.
* Переданный `get(url, limit, *, accept)` возвращает байты с ограничением размера. Для JSON есть `fetch_json`. Сбой одного модуля получения полного текста позволяет перейти к следующему. В диагностике по PDF сохраняются имя адаптера и статус HTTP, если он известен.

Проверка контракта запускается из корня репозитория командой `python -m unittest discover -s tests -p test_source_contract.py -v`. Тест подключает отдельный источник с обязательным полем, создаёт библиотеку через HTTP и проверяет полученные через сервис байты PDF.
